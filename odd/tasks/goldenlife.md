# GoldenLife (Cademí) platform + Windows rename fix

Objective: download courses of https://my.goldenlife-academy.com (Cademí LMS) from Lumen, show the Golden Life logo in the download options, and fix the Windows `WinError 32` on the final yt-dlp rename. Branch: `main` (work-unit commits). Delivery strategy: ask-on-risk. Runner: `cargo test --workspace`, `cd ui && pnpm test`.

## Specs

- S1 (user): "desarrolles ahora la opción para descargar los videos del enlace https://my.goldenlife-academy.com/auth/login incluye el logo en las opciones de descarga, usa las credenciales en la carpeta secure sin publicarlas en el repo, haz las pruebas necesarias sobre los modulos y videos de los cursos de esta plataforma".
- S2 (user): "revisa este error en windows" — `[WinError 32] El proceso no tiene acceso al archivo porque está siendo utilizado por otro proceso: '…Lesson.temp.mp4' -> '…1. Lesson.mp4'`, URL `vod-akm.play.hotmart.com/…/master-pkg-t-….m3u8` (Hotmart, `Limpiezas Energéticas`, 18 of 19 downloaded).
- S3 (derived, verified live 2026-10-25): login is a Laravel form POST `/auth/login` with `_token` (CSRF), `Acesso[email]`, `Acesso[senha]`, `Acesso[lembrar]=1`. Success = 302 to `/area/vitrine/home`; wrong password = 302 back to `/auth/login`. `Acesso[lembrar]=1` adds a ~400-day `remember_cademi_*` cookie (session cookie lives 2 h).
- S4 (derived): catalogue = `/area/vitrine/home` shelves (`div.vitrine` > `.main-title span`) with products `a[href=/area/conteudo/produto/<id>]` (`aria-label` = title, cover `img`). Product page redirects to its first lesson `/area/conteudo/aula/<id>`; the sidebar (`.section-group[data-acesso-secao-id]` with `.section-group-titulo .item-titulo` and `a[href=/area/conteudo/aula/<id>]` items, rendered twice: desktop + mobile, dedupe by id) lists sections and lessons. A product whose redirect lands on a lesson of ANOTHER product (`data-acesso-produto-id` differs) has no content of its own (aliases of the "RETO VIP" shelf): report as the "no modules" issue.
- S5 (derived): lesson page: main player `div.video.video-pandavideo[data-id]` with iframe `https://player-vz-<lib>.tv.pandavideo.com.br/embed/?v=<id>`; HLS = `https://b-vz-<lib>.tv.pandavideo.com.br/<id>/playlist.m3u8` (no DRM, no AES; Referer `https://my.goldenlife-academy.com/`; yt-dlp verified). Body `article.aula-conteudo` = rich text (`.article-paragraph`, `.article-header`, `figure`, `a.article-link`), embedded `div.video-youtube[data-id]` (6 seen), attachments `a.article-attach[href=/area/arquivo/anexo?…&n=<name>&signature=…]` (72 seen). A lesson may show `URL no identificada` instead of a video (1 seen) and many are text-only (57 of 453).
- S6: layout identical to Hotmart: `<library>/GoldenLife/<course>/<N. section>/<N. lesson>/{N. Lesson.mp4, Description.html, Materials/…}`; one course = one product; scanner ids `goldenlife/<folder>`, lesson keys `goldenlife:…`.
- S7: never fail silently: unresolved video/attachment/lesson page => Issue in the report; `.complete` only without error issues; a lesson with no content at all => warning `EmptyLesson`; `URL no identificada` => warning `VideoNotResolved` (a gap on the platform's side must not make the course permanently incomplete); session expiry mid-run => re-login via remember cookie, else stop with "session expired" issue.
- S8: secrets: email/password only live in memory for the login call; persisted session = cookie header only (restricted perms, same store as the other platforms); never logged; `Debug` redacted; `secure/` is git-ignored (verified `.gitignore:43`) and never read by non-ignored tests.
- S9 (contract, additive): Tauri commands `goldenlife_login_credentials(email, password) -> {loggedIn, courses}`, `goldenlife_session_status`, `goldenlife_logout`, `goldenlife_courses`, `goldenlife_download_start(course)`, `goldenlife_download_cancel(id)`, `goldenlife_downloads_running`. Course JSON: `{id: string|null, title, shelf: string|null, imageUrl: string|null, folder, issue: string|null}`. New error code `invalid_credentials`. Events carry `platform: "goldenlife"`.
- S10: Windows fix: when yt-dlp fails with a Windows "in use by another process" rename error (`WinError 32`, `.temp.<ext>` -> `<ext>`), Lumen retries the rename itself with bounded backoff before cleaning; yt-dlp also gets `--file-access-retries`. Failed runs still clean leftovers.
- S11: UI: platform tile with the Golden Life logo (assets `ui/src/assets/platforms/goldenlife.webp`, `goldenlife-mark.webp`, already added), email+password connect form, course list grouped by shelf, library tab, i18n es+en, mock, tests.
